# grill prompt 骨架 — 场景 B 的固定结构

这是被验证「既狠又躲得过 AUP」的 grill prompt 结构。活范本见 `docs/superpowers/reports/2026-07/` 下已有的多份（如 `*-deterministic-vs-llm-boundary-*` `*-container-state-ownership-*`）。

## 整体结构：两段分明

```markdown
# Grill prompt · <一句话主题>

> 给 Fable 的纯抽象设计评审。**背景**：<两三句说这是什么系统、要拷问什么>。
>
> **本文档为纯抽象表达，不含业务隐喻，措辞中性。转给 Fable 前请原样贴下面「PROMPT 正文」整段。** 上半背景是给你(用户)看的，不要贴。

---

## 背景（给用户，不贴给 Fable）

- **已落的既定裁决/前提（本评审不重开）**：<列出不该被 grill 重开的东西>
- **要 grill 的对象**：<spec/plan 路径>
- **核对到的现状事实**：<grep 核实过的、Fable 要用到的事实，编号>
- **要 grill 的深层张力**：<这次真正想被推翻的预判是什么>

---

## PROMPT 正文（贴给 Fable）

你在评审一个<系统类型>的架构设计。<一句话定位>。系统已定下一套架构裁决（下称"既定裁决"，本评审不重开），现要<评审什么>。

### 系统设定（固定）

- <用纯抽象术语描述系统：内核/边缘/账本/单元/状态通道……>
- <既定裁决用抽象话复述，Fable 要靠它做判断>
- <被评审的新设计，抽象描述>
- <软决策列出来：spec 里"待定/倾向/候选"的，标"要你评">

### 要你评审的问题（逐条）

**1.（<问题眼>）<问题正文>**
   - <给判据方向，但不给答案>
   - 关键问题/张力：<瞄准一个软肋，逼它攻击预判>
   - 给出<结论X>的结论 + 判据。

**2.（...）...**（每问瞄一个软肋；若答案取决于别问，明说依赖链）

### 输出要求

- 第 1 问给 **<结论类型>**。
- （逐问列）
- 最后 4-6 句收敛："<A> = ___；<B> = ___，判据 = ___；<C> = ___（取决于 ___）。"
- **只谈这几个问题。** 不重开既定裁决、不引入具体技术选型细节、不引入业务领域名词。给**结论**而非只给判据。若某问的正确答案取决于另一问，明说依赖链。
```

## 写好每一环的要点

- **系统设定必须纯抽象**：把业务实体翻译成"系统/单元/内核/边缘/账本/隔离键/状态通道"。Fable 不需要知道这是行为学分析系统——抽象反而让它专注逻辑。**顺带天然躲过 AUP**（业务隐喻常是触发源）。
- **每个问题瞄一个软肋**：不问"这样对不对"，问"X 是 A 还是 B、判据是什么、与既定裁决 Y 有没有张力"。软肋来源见 SKILL.md 场景 B 的 B1。
- **要"结论 + 判据"**：Fable 爱只给判据不给结论。输出要求里明写"给结论而非只给判据"。
- **标依赖链**：问题间常有依赖（问3 的答案取决于问2）。让 Fable 明说，避免它各问孤立答。
- **收敛句模板**：结尾给一个填空式收敛句，方便裁决回来后落 decision-record。
- **限定范围**："只谈这几个问题、不重开既定裁决、不引业务名词"——防 Fable 发散或重开定案。
